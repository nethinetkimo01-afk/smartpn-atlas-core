# SmartPN 系統 UX 修正規格（2026-06-20）

## 背景
使用者（Jim）指出系統在「使用者方便性與易懂性」上的多項缺陷。本規格將這些問題整理為可執行的修正任務，並訂出全系統 UX 鐵則，未來所有界面任務皆須遵守。

---

## 一、全系統 UX 鐵則（永久標準，每個界面都要套）

1. **存檔行為比照 Excel**
   - 直接「儲存」= 靜默存檔，不跳對話框，存完只給一個輕量提示（如底部一行「已儲存 ✓」，2 秒後消失）
   - 只有「另存新階段」才跳確認對話框
2. **功能必須有看得到的入口**
   - 任何功能（帳號管理等）都要有頂部列按鈕或選單入口
   - 嚴禁要求使用者記網址、手打網址才能用
3. **格子一眼可辨**
   - 手工輸入格 = 明確白底 + 清楚灰色細邊框(1px solid #C7C7CC)，常駐顯示成框（空值/有值框都清楚）
   - 自動計算格 = 無框、無底色、純黑數字
   - 嚴禁「點了才出現輸入框」
4. **配色克制統一**
   - 表頭列、分區列可有顏色
   - 其餘所有儲存格：白底、純黑字(#000000)
   - 所有操作圖示(＋、✕、合 等)：純黑
   - 不亂用顏色
5. **易懂優先**
   - 設計時先想「使用者第一次看到，懂不懂、找不找得到」，而非只完成功能

## 二、本次具體修正任務（一次做完，不發揮）

### 任務 1：存檔不跳對話框（比照 Excel）
**檔案**：ie_cell_detail.html（其他有存檔的頁面同步）
**現況問題**：「儲存 ▼」下拉裡的「儲存」呼叫 showSaveModal()，每次存檔都跳對話框。Excel 直接存檔(Ctrl+S)從不跳框。
**要求**：
- 「儲存」按鈕改為：直接靜默存檔（呼叫實際存檔 API），成功後在 save-bar 顯示「已儲存 ✓」輕提示，約 2 秒後淡出。不跳任何 modal。
- 「另存新階段」維持跳確認框（這是建立新版本，需要確認，符合 Excel「另存新檔」邏輯）
- 若有未存變更，可在 save-bar 顯示「有 N 項待儲存」，按儲存後清掉
- 不改實際存檔的後端邏輯，只改「存檔不跳框」的前端行為

### 任務 2：加「帳號管理」入口按鈕
**檔案**：ie 相關頁面的共用頂部列（topbar）、bianche.html 等有 topbar 的頁
**現況問題**：帳號管理只能手打 /admin/users 進入，沒有按鈕入口。
**要求**：
- 在頂部列加一顆「帳號管理」按鈕，點擊開啟 /admin/users
- 此按鈕只對 role=admin / manager 顯示，data_entry / read_only 不顯示
- 樣式與頂部列其他按鈕(如「矩陣」「DS-03」)一致

### 任務 3：手工格統一明確白框
**檔案**：ie_cell_detail.html
**現況問題**：「裁機要求人數(No.of Oper.)」欄的白框明確清楚，但其他手工格(層數、件數、刀數/H、各分頁手工標時/實際人數)的框偏淡，有值時看不出可輸入。
**要求**：
- 以「裁機要求人數」欄現用的明確白框樣式為基準
- 所有其他手工輸入格統一成同款：白底 + 清楚灰色細邊框(1px solid #C7C7CC)、常駐、空值/有值框都清楚
- 涵蓋所有分頁(裁斷/針車/成型/STF)
- 自動計算格維持無框純數字

### 任務 4：確認 manager 能進帳號頁並新增帳號
**檔案**：app.py（admin_users_page）
**要求**：
- 確認 /admin/users 頁面開放給 admin 和 manager（若目前只給 admin，開放給 manager）
- manager 進入後能新增 manager/data_entry/read_only 帳號（建 admin 仍應被擋，維持 49b3dcf 的提權防護）
- 不破壞現有提權防護
