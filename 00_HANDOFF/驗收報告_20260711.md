# Task B｜裁斷合併 bug 診斷（只診斷，不修）

完整診斷見 `test_screenshots/cutting_merge_diag/DIAGNOSIS.md`。材料：01–05 截圖 + diag_data.json + unsaved_edit_test.json。

## 真因定位
**真因＝合併觸發的整段重載 `loadSegment()` 丟棄「未提交」的層/件/刀編輯**（已重現，LOST=true）。
- 層/件/刀輸入格（`ie_cell_detail.html` `renderCuttingRow`/`edMA` ~L908）只有 **blur 才存**
  （`onblur=commitEditStatic`；`oninput=recalcCuttingStdByPid` 只重算不存）。
- `submitMerge()`(~L1708) / `saveGroupHc()`(L1650) / `unmergeGroup()`(L1664) 存檔後呼叫
  `loadSegment(SEG)`(L751)：`EDITS={}` + 重新 fetch + `renderZones` 整段重繪 → 未 blur 的輸入被伺服器舊值覆蓋。
- 重現：層數輸入 `99`（不 blur）→ 合併重載後變回 `2`（`unsaved_edit_test.json`: LOST=true）。

## 反證：已儲存資料的合併渲染是**正確**的（不是渲染錯位）
- 連續合併(seq1,2,3) / 非連續合併(seq1,3) 前後，層/件/刀值全數保留；
  群組首列出 rowspan 群組格、非首列 td 少 1（實際人數欄被 rowspan 蓋，正確）；非連續時成員自動重排相鄰以對齊 rowspan。
- 即 rowspan / 群組列 / 欄位對齊**無缺陷**（推測 Task086/087 rowspan 重寫已修純渲染面）。

## 修復方案建議（未改任何程式碼，等 Jim 拍板）
- **A 最小**：`submitMerge`/`saveGroupHc`/`unmergeGroup` 在 `loadSegment` 前先 `blur()` + await 進行中的 commit，確保先存再重載。
- **B 治本**：合併成功後不整段重載，只局部更新受影響 zone 的 tbody（插入 group 格），保留其他未存輸入。
- **C 防呆**：層/件/刀改 `input` 去抖動即時存，或 dirty 追蹤＋重載前自動提交。
