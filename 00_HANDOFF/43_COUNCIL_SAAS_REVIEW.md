## 已定案

### 責任模型（Jim 定案）
- SmartPN 負責「資料的交換」；資料提供者對資料正確性負全責，
  並對其負法律責任。此原則寫入 SmartPN 使用條款公告。
- 類比：食品成分表——食品製造商對成分表內容負全責。
- 「SmartPN Verified」不得存在。交換平台無法保證內容真偽，
  驗證背書一律歸第三方發證機構（顯示發證單位 + 證書效期）。
- DPP-ready 定義為「欄位齊全度」狀態（系統自動檢查），
  對應憲法 Readiness Governance：Ready to Publish / Missing Metadata。
  不代表內容經驗證。

### Demo 違規追加（待修）
- SMARTPN_DEMO.html 與 SMARTPN_DEMO_SUPPLIER.html 認證表中
  「DPP-ready · SmartPN Verified」字樣移除，改為第三方發證機構
  或欄位齊全度標示。

## 第二輪定案（Jim 逐項裁決）

### D1 共同開發保護
不加新機制。permission control 就是答案：私密/僅授權的材料不會出現在
任何人的 Find Same Material 結果中；公開＝自願上架。
工廠與供應商的獨家約定是雙方商業合約，平台不介入。

### D2 需求雷達（供應商匿名聚合搜尋訊號）
待討論。治理原則已定：賣方有想獲得買方資訊的權利，
買方同樣有決定是否透露的權利（買方同意權優先）。

### D3 版本與存證
- 公開資料：SmartPN 內建版本記錄（修改留痕）。
- 私密資料：零存放不變；交換雙方可各自在自家 API 端做版本記錄。
- 交換存證＝選配：SmartPN 只留交易記錄、不留交易內容；
  或由 supplier API 只推送修改記錄+交易記錄作存證。
  存證記錄永不進入可搜尋資料庫。

### D4 責任切分（mapping 錯誤）
架構自答：私密資料 SmartPN 看不到內容，無從驗證 mapping 正確性，
唯一驗得了的是資料擁有者。
- 驗收簽署為啟用前強制步驟：未驗收的 mapping 批次不上線、不交換。
- 簽署後，資料正確性責任歸提供方（食品成分表原則）。
- Mapping 方法論：分批進行（依品牌需求：財務→關務→物性…），
  一次全量 mapping 錯誤率高。

### D5 計費結構
1. 永不按營業額/交易量抽成——結構上不可能：平台賣帳號，
   交易與進銷存不經過 SmartPN，無抽成基礎。
2. 席次不封頂，以量制價。定價不錨定現階段交換範圍
  （未來可交換每月財務、每月報關等，價值隨範圍成長）。
3. Pilot 不免費。風險控制改用帳號隨用隨增（不必一次購足）。
4. 創始供應商無免費/折價條款。GTM：品牌先行，供應商跟隨品牌腳步，
   先機本身即紅利。

### D6 比價功能承諾
不寫入條款。permission control 全權治理：
- 價格設私密＝平台無從洩露；場外私下洩露是人的行為，平台不負責。
- 公開是資料擁有者同等正當的選擇——若供應商自願公開價格，
  全平台帳號有知的權利。平台不為想隱藏者封殺自願公開者的功能。

### 退出權
帳號失效＝所有資料存取失效。離開方可匯出自己維護/發布的資料；
SmartPN 核發的統一料號為 SmartPN 財產，不交付。

## 貫穿性規則
所有定案必須設計進 SaaS 介面，不得只存在條款或白皮書。

## SaaS 介面設計需求（由定案導出）
1. 欄位級來源標示：Source System / Authority / Sync Time / Cached or not（品牌條件①）
2. 搜尋結果權限標示：「N results visible to you」+ permission-filtered 提示（品牌條件③）
3. Permission control 三態貫穿所有資料：公開 / 私密 / 授權給指定對象
4. Mapping 驗收流程頁：分批 mapping → 擁有者端測試核對 → 簽署啟用 → 未簽不流通
5. 交換存證選配開關（只記錄、不記內容、不可搜尋）
6. 公開資料版本歷史視圖
7. 帳號隨用隨增的購買流程
8. 匯出自有資料功能（退出權）

## 第二輪後三方立場

  D3/介面需求 1、2、5 已回應）
- 供應商：有條件分階段第一批上（其五條件中：價格條款→D6 裁定不寫、
  需求雷達→D2 待討論、退場→退出權已定、分階段上傳→符合現有設計、抽成→D5.1 結構性解決)
- 工廠：有條件小規模 pilot（其四條件中：權限矩陣→介面需求 3、代接 SLA→D4、
  計費封頂/pilot 免費→D5.2/5.3 裁定不給、退出→已定）

## 尾輪裁決（全數關閉）

### 影子 BOM／去中間化 — 關閉
此非漏洞，是 S05 設計本意。正確流程：品牌定義 Shared BOM 同步各工廠
→ 各工廠依所在地，用搜尋找品牌核可的當地供應商 → 申請替代 → 品牌核准。
品牌因此看到各廠實際 BOM 與 Shared BOM 的差異及價差——這正是產品
販售的透明度。搜尋的主要使用者是工廠（找當地替代料），
工廠自身採購成本在報價單中，一單一授權，不交換即不外流。

### D2 需求雷達 — 結案為「保留空間」
本期不做。未來依買賣雙方實際需求新增，架構預留擴充位。
治理原則維持：買方同意權優先。
