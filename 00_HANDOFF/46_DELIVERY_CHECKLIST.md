## 一、建造者（Builder）＝ 入場券，不是通過

- [ ] `python hub_ci.py` 全綠（13/13，含閘門13 breaker_gate）
- [ ] 報告附**輸出全文** + **閘門檔 hash**（自證判定未被修改）
- [ ] 未修改任何 `GATE_FILES` 判定邏輯（改判定＝作弊，直接作廢）
- [ ] 新端點已納入 `breaker_gate.py` 攻擊面

### ★ 資料來源自證（本次新增 — 血的教訓，見附錄）

hub_ci 每次啟動會印「來源身分」橫幅。**貼上該橫幅**，不要只貼「ALL GREEN」：

```
▸ 來源身分：ie_process=____ 列, ob_header=____ 列, 有 actual 的 header=____
```

- [ ] 上列數字與 **Jim 真庫**相符（ie_process ≈ 20434、有 actual 的 header ≈ 140）
- [ ] 若出現 `⚠️ 只有 N 個 header 有 actual 資料` → **本次交付不得宣稱任何與真實資料有關的結論**

> 「複製忠實」≠「來源是真庫」。閘門全綠只證明**程式**對，不證明**資料**對。
> 綠燈是在你餵的那份資料上綠的。

## 二、破壞者（Breaker）＝ 獨立視窗

立場：這東西一定有 bug，我的工作是弄壞它。逐項附證據。

- [ ] 亂點：連點 / 空狀態點 / 快速切換
- [ ] 並發：同時 N 個相同請求（匯入 / 儲存 / 重算）
- [ ] 壞資料：半截檔 / 空值 / 超大值 / 注入字串 / 全形 / 錯型別
- [ ] 邊界：0 筆 / 1 筆 / 最大筆數 / 缺前置條件就執行下一步
- [ ] 權限繞過：低權限帳號硬打高權限端點
- [ ] 狀態殘留：做一半離開 / 回退 / 切月份或版本後原值殘留

輸出格式：**我試了什麼 → 結果如何 → 這是不是 bug**。不接受「我覺得還好」。

判定：🟢 攻不破 ／ 🔴 攻破 ___ 處（附最小重現）

## 三、對規者（Spec-Auditor）＝ 獨立視窗

立場：不符 Jim 的原始規格檔就是錯，我不看 Code 說什麼。

- [ ] 只讀規格檔（28_BIANCHE_SPEC / 16_S02_TO_S17 / 27_WORKING_RULES）
- [ ] 逐條、逐欄、逐結構維度對帳（**所有**單位/月份/角色/EOLR，不是抽一個）
- [ ] 覆蓋率量化：驗了 ___ 個實例 / 規格要求 ___ 個 = ___%
- [ ] 數字可追溯：每一格能從來源算出（不是「有這個欄位」就算過）

判定：🟢 全條符合 ／ 🔴 不符 ___ 條

---

## 四、使用者（User-Sim）＝ 獨立視窗

立場：我是不看說明、會亂搞的工廠新人，走不通就是 bug。

- [ ] 照真實流程從頭走到尾（匯入→勾選→計算→導出／申請→授權→交換）
- [ ] 每步斷言**畫面實際變化**（不是 API 回 200）
- [ ] 只用真實點擊路徑，不呼叫內部 API、不走捷徑
- [ ] 死路 / 空白 / 數字錯 → 記錄

判定：🟢 全程走通 ／ 🔴 卡在第 ___ 步

## 五、裁決者（Arbiter）＝ 中樞

- [ ] 用 **Jim 的真實 atlas.db** 獨立複跑閘門（不是用 Code 給的副本）
- [ ] 交叉比對：破壞者說壞、建造者說好 → **以破壞者的可重現證據為準**
- [ ] 四方全綠？（全票制，任一紅即退回）

**最終判定：** ⬜ 放行（可對 Jim 說「可以看」） ⬜ 退回（自動生成退回令給 Code）

## 附錄｜為什麼加「資料來源自證」（2026-07-15 實例）

中樞認定 `clone_prod_db()` 有 bug：「複製 20434 列真庫卻只得 8295 列 / 3 header → 漏抓」，
指示改用 `shutil.copy2`。實測結果：

- 來源 `flask_backend/data/atlas.db` **本身就是** 8295 列 / 有 actual 的 header = 3。
- backup API 與 copy2 兩種複製法，**37 表逐表列數與來源完全相同** → 複製沒有漏抓。
- 根因：`flask_backend/data/` 在 `.gitignore` 內（commit 323f561），**真庫從不經 git 同步**。
  本機這份是留在開發機上的舊副本，ME129 的真庫從來沒下來過。

教訓：**閘門全綠，是在你餵的那份資料上綠的。** 沒有來源身分自證的綠燈，
證明的是「程式在假資料上對」，不是「系統對」。
若當時真的改成 copy2，不但一列都不會多，還會失去 backup API 對線上 WAL 庫的一致性保證
（對線上庫 copy2 會取到撕裂檔）——把一個不存在的 bug「修」成一個真的 bug。

→ 故本清單第一項不是「綠了嗎」，而是「**你測的是哪個庫**」。
