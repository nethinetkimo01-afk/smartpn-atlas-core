## 1. 為什麼要做

2026-07-12 Jim 定案：裁斷機標時公式 `3600÷刀÷層×件` 取消 ×1.1 係數（見 27_WORKING_RULES §二①）。

- **細表（前端）**：`ie_cell_detail.html fmCutA()` 已即時以 **×1.0** 顯示，且刻意「忽略 DB standard_time，由三要素現算」。
- **bianche（編制表）**：`database.py get_bianche_data → zone_theory` 讀 **DB 的 standard_time**（`Σ std × eolr/3600`），且 `get_bianche_data` 只納入 `standard_time>0` 的列。
- **落差**：裁斷機公式列在 DB 若存的是早期匯入的來源 Excel **×1.1 基礎值**，或存 **NULL**（新版存檔設計把裁斷機存 NULL 交前端現算）→ bianche 會用到 ×1.1、或整列被漏算。**細表對、bianche 錯。**

方案a＝把「公式型裁斷機列」的 DB standard_time 重算為 ×1.0，讓 bianche(讀 DB) 與 細表(即時×1.0) 一致。**bianche 維持讀 DB 值，不改即時算（鎖定版＝快照語意）。**

## 2. 重算範圍（只碰公式型裁斷機列）

```
segment='cutting' AND zone='裁斷機'
AND cut_per_hour>0 AND layers_per_cut>0 AND qty_per_pair>0   -- 三要素齊全＝公式列
AND (value_type IS NULL OR value_type != 'manual')            -- 手工列不動
AND (flag IS NULL OR flag != 'deleted')
```
公式：`standard_time = 3600 / cut_per_hour / layers_per_cut * qty_per_pair * 1.0`（與前端 `fmCutA()`/`_rowStd()` 完全一致，存完整浮點不四捨五入）。

**一律不動**：ATOM / EMMA / Laser / YINGHUI / 移印 / 轉印（手工標時區）；裁斷機區內缺三要素的手工列、`value_type='manual'` 列、已刪除列。

**理論人數**：系統各處（細表 `_calc_theory`、bianche `zone_theory`）皆即時由 `standard_time ÷ (3600÷eolr)` 導出，未獨立存欄 → 重算 standard_time 即**連動**更新理論人數，無需另改。（`allocation_item.theory_mp` 是「撥人快照」另一機制，非本次目標；要同步撥人需另跑撥人流程。）
