# SmartPN Atlas ??Operating Rules
Version: v1.0 | 2026-05-28

## Output Labels (required on every output)
- CLIENT-READY: passed all checks, can show to Jim or customer
- INTERNAL STRUCTURE ONLY: useful for planning, not for customer demo or publishing
- REJECTED / DO NOT USE: wrong, incomplete, inconsistent, or contradicted by Jim's rules

## Pre-Output Checklist (check before every response)
1. Did I read the operating manual or relevant MD?
2. Am I using SmartPN Atlas correctly? (never SmartPN alone)
3. Did I check existing assets before generating new content?
4. If LinkedIn radar: are targets individuals, not company pages?
5. If website change: local preview only unless Jim approved production?
6. If visual: understandable in one glance?
7. Am I making Jim QA basic errors?
8. Output focused on manufacturing-side positioning?
9. DPP only as downstream example, not main topic?

## Mandatory Forbidden Actions
- Use SmartPN alone (always SmartPN Atlas)
- Use LinkedIn angle as scenario title
- Rename/reorder scenarios without instruction
- Position Atlas as ERP/PLM/BOM/marketplace/DPP generator
- Auto-publish LinkedIn content
- Deploy website without Jim approval
- Claim automation works unless verified
- Use company pages as primary LinkedIn radar target
- Invent demo menu, mock data, supplier names, ID format
- Use 17 scenarios as demo navigation menu

## PPT = Demo = Source-of-Truth
Every customer-facing scenario PPT must match demo software exactly.
Field names, mock data, colors, status words must be identical.
If PPT and demo differ, both are not client-ready.

## Required Closing Line (important outputs)
Rules checked: naming / existing assets / personal-post filter / production safety
